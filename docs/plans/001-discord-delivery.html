Plan 001 — Discord チャンネル配信（メール併用）

Status: done  ·  Plan ref: plan:001  ·  Guild: 1240905723555086336

Intent & scope

メールが使えない状況の代替として、生成済みニュースレターをテーマごとに別の Discord チャンネルへ GitHub Actions（無人実行）から自動投稿する。既存の Resend メール配信は残したまま併用する。

スコープ外: メール配信の停止・置換、Discord Embed / リッチカード整形、スレッド/リアクション、 リアルタイム双方向連携、Firestore への channel ID 投入（運用データ設定であり別途）。

設計判断（確定事項）

論点決定理由
認証Discord Bot Token（REST API v10）token 1つで channel をメッセージ単位指定でき、Firestore の動的テーマに追従。Webhook はチャンネル数だけ Secret が増える。
channel 設定の所在Firestore themes/{id}.discordChannelId既存の Firestore 中心設計と一貫。テーマ追加でコード変更不要。
メール併用（Resend は現状維持）ユーザー要望。Discord は独立ステップで追加。
本文フォーマットnewsletter-{id}.txt 全文を投稿ユーザー要望。HTML は Discord 非表示。
2000字制約行境界優先で ≤2000 字に分割し順次投稿Discord の1メッセージ上限。txt は約6.7KB。
失敗時の独立性Discord ステップは continue-on-errorDiscord 失敗がメール配信や workflow 全体を巻き込まない。

Acceptance criteria

各項目は検証可能。inspector はこれに照らして GO/NOGO を判定する。
  • AC1: fetch-themes.ts が Firestore テーマの discordChannelId（文字列）を読み取り、 output/themes.json の各要素に含める。未設定テーマでは省略される。
  • AC2: DiscordSender の分割ロジックが、テキストを行境界優先で ≤2000 字のチャンク列へ分割する。 単一行が 2000 字超の場合は強制分割する。空入力では空配列。ユニットテストで検証。
  • AC3: DiscordSender.post(channelId, text) が各チャンクを POST https://discord.com/api/v10/channels/{channelId}/messages に Authorization: Bot <token> ヘッダ付きで順次送信し、HTTP 429 時は応答の retry_after に従ってリトライする。fetch をモックしたテストで検証。
  • AC4: scripts/post-to-discord.ts が output/themes.json を走査し、 discordChannelId を持つテーマについて output/newsletter-{id}.txt を投稿する。 channel 未設定テーマはスキップしログ出力。DISCORD_BOT_TOKEN 未設定かつ対象テーマありの場合は エラー終了（exit 1）、対象テーマなしなら正常終了（exit 0）。
  • AC5: .github/workflows/newsletter.yml に Discord 投稿ステップが追加され、 has_themes==true かつ dry_run!=true で実行される。既存のメール送信ステップは温存（併用）。 Discord ステップは continue-on-error: true でメール配信を阻害しない。
  • AC6: npm test 全 green、npm run build 成功、npm run lint パス。
  • AC7: README.md / README.ja.md / .env.sample に Discord Bot Token と discordChannelId の設定手順が追記される。

実装メモ（契約の固定点）

  • npm スクリプト名: post-to-discord → npx tsx scripts/post-to-discord.ts。ビルド後の CI 実行は node dist/scripts/post-to-discord.js。
  • 環境変数: DISCORD_BOT_TOKEN。GitHub では Secret として設定。
  • themes.json の要素に discordChannelId?: string を追加（後方互換: 省略可）。
  • 分割の安全上限は 2000 字（余裕を持たせ実装側で定数化、例 1900）。チャンク間は軽い遅延 + 429 の retry_after 尊重。
  • Discord ステップは send-newsletter の後段に置き continue-on-error: true。

Open questions / risks

  • 運用前提（コード外）: Bot がギルド 1240905723555086336 に参加済みで、各対象チャンネルに「メッセージ送信」権限を持つこと。
  • データ投入（コード外）: 現行2テーマ（AIコーディング / マリンテクノロジー）の Firestore 文書に discordChannelId を設定する必要がある。未設定テーマは投稿スキップ。
  • Secret 設定: GitHub に DISCORD_BOT_TOKEN Secret を追加する必要がある。
  • txt 先頭の ==== 罫線等が Discord markdown で意図せぬ装飾になる可能性 → 必要なら投稿時に軽く正規化（T1 で判断）。
